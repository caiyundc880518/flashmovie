## 1. 版权交易（商业深度扩展）

### 1.1 现状
- IP 资产已有**版权交易**：卖「电视剧/游戏」版权给外部公司，固定总额每周分期（12/20 周），双版权可并行、期满可再签（`sellCopyright` action + `ip.deals`）。
- 缺口：**交易类型单一**（只有两类买断式）、**无玩家买入**、**与电影二级市场脱节**、**无谈判/定价机制**。

### 1.2 目标
1. **电影版权二级市场**：已下片/完结的电影可以把"某渠道再发行权"或"全版权"卖给平台或其他公司（买断 or 分成），老片库变成可管理的资产。
2. **IP 版权类型扩展**：在电视剧/游戏之外增加 动画 / 舞台剧 / 授权商品 / 主题合作，不同类型有不同价格曲线与冷却。
3. **玩家买入版权**：从市场或**竞对公司**手里收购 IP 版权/片库（与 #2 公司收购联动）。
4. **定价机制**：价格 = f(累计票房、IP 热度、影评口碑、类型潮流、双方声誉)；买断 vs 分成（分成 = 每周/季度按票房比例入账）。

### 1.3 核心设计
- 新实体 `LicenseOffer`：市场刷出版权出售/求购单（片源、类型、买断价 or 分成比例、剩余期限）。
- 项目侧新增 `filmLicenses: LicenseDeal[]`：已下片影片的版权出售记录（与 IP 版权 `deals` 并列，电影版权 ≠ IP 版权，可同时存在）。
- 定价纯函数 `licensePrice(state, film | ip, mode)` 走配置表，供 UI 预估与结算共用。
- 与 NPC 联动：NPC 也会买/卖版权（快发型爱卖断回血、品质型爱捂 IP），产生市场新闻。

### 1.4 平衡与迁移
- 新增 `FilmProject.filmLicenses` / `World.licenseMarket` 字段 → **存档 v16**。
- 防死局：老片库卖断是现金流保底手段之一；分成比例上限防刷钱。

### 1.5 验收
- 已下片电影可挂售/被求购；买断与分成两条现金流路径可结算；
- 玩家可从竞对收购 IP 版权；NPC 参与市场并有新闻；
- 规则层单测覆盖定价/结算/再签；旧档迁移无损。

## 2. 公司收购（长线经营大系统）

### 2.1 现状
- 竞对影业有完整数据（声誉/资金/团队/IP/片库/性格），玩家可挖角员工——但**公司本体不可交易**，游戏没有"终局目标"级别的商业动作。

### 2.2 目标
1. **玩家收购竞对**：现金（+上市后股权）收购对手 → 获得其团队/IP/片库/历史 → 整合（保留品牌 or 并入主公司、留用/裁员、继承 IP 续作权）。
2. **玩家被收购**：满足条件（上市、高估值、对手巨头出现）时触发收购邀约 → 成为可选**结局**（套现离场）或拒绝。
3. **NPC 互相收购**：大公司（高声誉+高资金）对小公司发起收购，世界格局动态变化（数量减少、垄断出现）。

### 2.3 核心设计
- 公司估值纯函数 `companyValuation(state, c)`：声誉 × 系数 + 现金 + IP 估值 + 片库估值 + 团队估值。
- 收购流程状态机：报价 → 谈判（溢价/分期/股权）→ 交割（资产合并）→ 整合期（员工整合/裁员新闻）。
- 整合规则：被收购方的 `team/ips/history` 并入收购方；玩家收购后 NPC 从世界移除（或降级为子公司），其**性格并入玩家可管理资产**。
- 结局系统：被收购 = 通关型结局（记录成就/统计 → 可继续沙盒玩）。

### 2.4 平衡与迁移
- 新增 `Company.subsidiaries?` / 收购记录 → **存档 v17**。
- 收购价需显著高于"自己经营"的机会成本，避免无脑买穿；贷款/上市额度联动。
- 与 NPC AI 联动：狙击型更爱收购竞争对手；破产救急时可被低价收购（新保底）。

### 2.5 验收
- 玩家可发起收购（现金/股权两途径）并完成交割整合；可被收购并进入结局页；
- NPC 之间会发生收购并改变排行榜/颁奖格局；
- 存档迁移 + 长线平衡测试（收购节奏不破坏现金流曲线）。

## 3. 员工培养（养成系统扩展）

### 3.1 现状
- 成长 = 参与项目（按表现拿经验/CA 成长 + 技能成长）+ 小游戏加成；空闲久了**衰减**（可作弊关掉）；属性 PA/CA、8 技能、名气/热度已有。
- 缺口：**主动培养手段缺失**（只能靠拍片）、无晋升/头衔、无忠诚/激励、无师徒。

### 3.2 目标
1. **主动培训**：培训课程（技能课程 / 明星培养 / 职业素养），消耗时间 + 资金，按周提升技能/CA/名气；训练营批量；课程有冷却与上限（PA 天花板约束）。
2. **晋升与头衔**：属性达标触发晋升（新星→明星→影帝/影后），头衔影响名气、薪资谈判、挖角抗性；**转职**（演员→导演等，消耗大但打开新路线）。
3. **忠诚与激励**：忠诚度（0–100）——受加薪/获奖/培训正向影响，被忽视/被压榨负向影响；忠诚影响被挖角成功率与流失风险；玩家可**加薪/发奖金/签长约**绑定明星。
4. **师徒制**：资深员工带新人，双方收益（新人成长加速、导师经验+忠诚）。

### 3.3 核心设计
- 员工新字段：`loyalty`、`title`、`training`（进行中课程）、`mentorId?`。
- 新 action：`startTraining / finishTraining / promote / giveRaise / setMentor`；课程配置表 `TRAINING`（课程/时长/成本/效果/上限）。
- 成长公式改造：`growth.ts` 增加"培训经验"通道，与项目经验**可叠加但有每周总上限**（防无脑刷）。
- 与挖角联动：忠诚度进入 `poachSuccessChance`（高忠诚明显更难挖）。

### 3.4 平衡与迁移
- Worker 新字段 → **存档 v16**（与版权交易同一版本打包，减少迁移次数）。
- 防膨胀：培训效果受 PA 上限约束；成本随时间/等级递增；总成长速率校准保持 longrun 基线。

### 3.5 验收
- 课程可开/可完成/有效果；晋升与头衔可见于员工卡与详情；忠诚影响挖角；师徒生效；
- 长线测试：培养策略下 IPO 周数/现金不崩、员工 CA 曲线平滑可控。

## 4. 沉浸感内容（公司/员工/世界历史档案）

### 4.1 现状
- 已有：`company.history`（影片记录）、`worker.career/awards`、新闻（最近 30 条）、TMA 颁奖、竞对详情页。
- 缺口：**时间线/年鉴式回溯**、**成长可视化**、**每部电影的一生档案**、**世界编年史**、**员工间关系**。

### 4.2 目标
1. **公司年鉴**：按年/按里程碑回溯（成立、首片、首奖、IPO、收购、年度财务汇总），生成"年度报告"（可浏览的历史页）。
2. **员工档案升级**：生涯时间线（入职/每部作品/培训/晋升/获奖/跳槽）、**属性成长曲线图**（PA/CA/技能随周变化）、头衔与"语录"。
3. **电影一生档案**：每部电影完整轨迹（筹备投入→上映→每周票房曲线→获奖→再发行→版权交易），在已上映详情页已有 5-TAB 基础上补**完整时间线**。
4. **世界编年史**：全局大事记页（对手动态/市场事件/影评人更替/收购/版权交易），支撑"世界在动"的沉浸感。
5. **员工关系**：搭档默契（化学反应的叙事化：好友/黄金搭档）、对头（抢戏/奖项竞争）。

### 4.3 核心设计
- 统一**事件流**：把所有重要动作写成结构化事件 `TimelineEvent { id, week, year, kind, payload }`，追加到 `company.timeline` / `worker.timeline` / `world.timeline`（替代/补充纯文本新闻，新闻可改为由事件渲染）。
- 成长曲线：每季度（或关键节点）给员工存一次属性快照 `worker.snapshots[]`，供曲线图（复用 LineChart）。
- 年报：年底由事件流聚合生成 `YearReport { year, boxOffice, awards, events }`，公司页展示。

### 4.4 平衡与迁移
- 存档体积：快照/事件需**有上限与抽样**（每员工每季度 1 次快照、事件按类型截断）→ **存档 v16**。
- 性能：时间线分页/懒加载；纯展示不参与结算，不影响平衡。

### 4.5 验收
- 公司/员工/世界三个时间线可回溯；员工成长曲线图随推进画出；
- 每部电影有一生档案入口；年报自动生成；旧档可无感迁移。

## 5. UI 美化（视觉打磨）

### 5.1 现状
- 暗色扁平编辑风（#0d1321 / 金色 #e8b64c / 钢蓝 #4c8bf5）、卡片化、多 TAB、限宽 1600、滚动数字已具备；用户偏好：大间距、铺满、弹窗、卡片、表格、图表不要柱状图（全部曲线图）。

### 5.2 目标
1. **设计令牌统一**：间距/圆角/阴影/层级梳理，建立 CSS 变量体系（部分已有），消除零散内联样式。
2. **动效细节**：入场动画、卡片悬停、弹窗过渡、金钱变化浮字、成就/里程碑庆祝弹窗（轻量，不干扰操作）。
3. **程序化电影海报**：按类型/评分/卡司生成风格化海报（渐变 + 字体排版 + 元素点缀），用于项目卡/详情页/年鉴，替代纯文字卡。
4. **图表升级**：统一曲线图组件（复用 LineChart 并增强：面积渐变、图例、多系列）；票房走势/成长曲线/年报可视化。
5. **响应式与性能**：平板适配；员工/影片长列表虚拟化（大存档性能）。

### 5.3 实现要点
- 纯 UI 层工作，**不改规则/存档**；逐屏重构并保持功能等价；每屏完成后肉眼验收（CDP 截图对比）。
- 海报 = 程序化（无图片资产），规则：类型色 + 评分等级 + 卡司名排版。

### 5.4 验收
- 全屏统一感（令牌一致）；关键动效流畅不掉帧；海报自动生成无错位；
- 桌面/平板无布局破损；现有 209 项测试与功能全绿。

## 6. AI 加持（动态文本 + 可选 LLM + NPC 意图）

### 6.1 现状
- NPC AI 已完成四阶段（性格/感知决策/口碑闭环/长线经营/团队挖角），但**全部文本来自模板池**（新闻、影评评语、事件描述、颁奖词），多周后会重复。

### 6.2 目标
1. **动态文本引擎（离线优先）**：结构化事件 → 组合式文案生成（模板 + 变量 + 同义池 + 轻微随机），让新闻/影评/事件/年报文本"不重样"，零依赖零成本。
2. **可选 LLM 接入**：架构预留「文本生成接口」（`TextGen` 抽象），默认离线模板实现；用户自备 API Key 时切换真实 LLM（生成影评评语、颁奖词、年报结语、剧情简介），**纯前端可访问的外部 API**（如 OpenAI 兼容接口）——需在设置里配置，明确数据只发文本、不发存档。
3. **NPC 战略意图**：NPC 每次决策产出结构化"意图"（为何拍这类型/为何避让/为何狙击），文本引擎渲染为**战略解读卡片**（竞对详情页展示），让 NPC 看起来"有想法"；若接 LLM 可升级为真正的"思考旁白"。
4. **LLM NPC 决策（可选进阶）**：对高价值决策点（档期/类型/收购）用 LLM 打分会与现有规则决策并存（规则兜底），架构上预留接口但**默认关闭**，避免可复现性与平衡被破坏。

### 6.3 实现要点
- 新增 `src/core/text/` 纯函数文案层（可单测），UI 层仅展示；LLM 走 `src/app/ai/` 适配层（不进入 core，保持规则层确定性）。
- 事件流（#4 沉浸感）是动态文本的主要数据源——**先做 #4 再做 #6.1** 最顺。
- 保密与性能：LLM 请求限频（每周/每事件一次）、失败回退模板、可关闭。

### 6.4 验收
- 连续模拟 50+ 周：新闻/影评/事件文本重复率显著下降；
- 竞对详情页出现"战略意图"卡片且与真实决策一致；
- 接 LLM 时（配置 Key）文本质量提升且失败自动回退模板；不接时全功能可用。

## 8. 待评审决策点（需要逐一确认）

1. **公司收购**：被收购结局是"通关即存档完结"还是"可继续沙盒"？（建议：可继续）
2. **员工培养**：培训是否需要"时间占用"（培训期间不能进剧组）？（建议：需要，形成取舍）
3. **版权交易**：电影版权与 IP 版权是否完全解耦？（建议：解耦，可同时存在）
4. **AI 加持**：LLM 是否值得做可选接入（需要用户自备 Key）？（建议：先做离线文本引擎，LLM 留接口）
5. **沉浸感**：事件流是否取代现有纯文本新闻？（建议：事件为数据源、新闻为渲染结果，兼容旧档）
